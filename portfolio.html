About

A sculptor's instinct for what's structurally wrong, now aimed at software.

I trained as a sculptor at Alexandria University's Faculty of Fine Arts, spending years learning to notice the flaw in a form before anyone else does — the joint that won't hold, the proportion that's slightly off. That instinct turned out to translate directly into QA: the same close, patient looking, just aimed at a login flow instead of a block of stone.

I completed a five-month software testing internship with DEPI (Digital Egypt Pioneers Initiative), finished Harvard's CS50, and I'm building out front-end fundamentals in HTML, CSS, and Java alongside manual testing practice with Jira and Selenium. I still work in Adobe's Creative Suite, and that visual training shapes how I think about usability, not just correctness.

Selected work

Account Validator

JavaHashMapFile I/O

Problem: a raw file held roughly 1,000 name and password records, mixed together with no separation between valid and invalid accounts.

Approach: wrote a Java program using a Map to check each record's name against an allow-list and route it accordingly, writing results out to two separate files.

Outcome: a working filter that sorts valid accounts from invalid ones automatically, and a much sharper sense of how defensive validation logic needs to be to hold up against messy input — a mindset that carries straight into test-case design.

Student Registration Form

HTMLCSS

Problem: build a clear, well-structured registration form rather than a flat pile of inputs.

Approach: grouped related fields with fieldsets, debugged the structure until it held together correctly, and worked through several iterations of the color scheme.

Outcome: a form that's easy to scan and use, and a first real exercise in treating markup structure and visual choices as one problem, not two.
